# Workshop format

The course is examined through three workshops. Each is a 2 h 45 min session where I present what I learned, demonstrate it live on the simulation, run a hands-on activity, lead two discussions, and answer the examiners' questions. The supervisors examine; doctoral peers take part.

| | Workshop | Learning outcomes | Hours budget |
|---:|---|---|---:|
| 1 | [Where authority leaks](w1-where-authority-leaks/) | K1.1–J1.6 | 70 |
| 2 | [Can deployed policy express it?](w2-can-policy-express-it/) | K2.1–J2.6 | 70 |
| 3 | [Can we prove it and measure it?](w3-prove-and-measure/) | K3.1–J3.6 | 60 |

Learning outcome IDs start with K (knowledge and understanding), S (skills and abilities), or J (judgement and approach), following the course ILO groups in the [syllabus](../docs/syllabus.md).

## A session

| Time | Block | What happens |
|---|---|---|
| 0:00 | The question | Where we are, the question of the day, and the learning outcomes |
| 0:10 | Talk and live demos (40 min) | Each claim is backed by a reading or by running an experiment in front of the room |
| 0:50 | Hands-on (30 min) | Participants work in pairs with the activity sheet and the simulator |
| 1:20 | Break | |
| 1:30 | Discussion A (30 min) | I lead; the question and readings are on the slide |
| 2:00 | Discussion B (30 min) | I lead |
| 2:30 | Examiner questions (15 min) | Open questions go into `log.md` and get a written answer within a week |

## What is in each workshop folder

| Path | Contents |
|---|---|
| `README.md` | Learning outcomes, agenda, story line, readings with IDs, experiments, hands-on, discussions, examination checklist |
| `slides/wN.tex` | The Beamer deck. It inputs `common/preamble.tex` and pulls results in with `\result{name}` |
| `experiments/` | `eK_*.py` scripts that write `results/*.tex` and `results/*.json`, plus the hands-on inputs |
| `activity/` | The one-page participant sheet (LaTeX, A4) |
| `notes/` | One Markdown note per reading, named by its ID |
| `log.md` | Preparation log, rehearsals, and follow-up after the session |
| `results/` | Generated; not tracked |

## Preparing a workshop

1. Read and take notes. `python tasks.py note R1.7` starts a note; log the time with `python tasks.py log`.
2. Build or extend the experiments, and run them with `python tasks.py run w1`.
3. Write the slides. Mark what still has to be checked with `\prep{}`, and build with `python tasks.py slides w1`.
4. Rehearse, record it with `python tasks.py rehearsal`, and change the deck.
5. Resolve every `\prep{}`, then build the presentation copy with `python tasks.py slides w1 --final`, the speaker copy with `--notes`, and the participant copy with `--handout`. Build and print the activity sheets with `python tasks.py activity w1`.
6. Run `python tasks.py dossier w1` and work through the workshop's examination checklist.
7. After the session, record the examiners' decision and answer open questions in `log.md`.

The last slide of each deck, "How this workshop was prepared", is generated by the dossier, so the examiners see the same numbers as the repository.

## The running scenario

All three workshops use one scenario, drawn in [common/scenario.tex](common/scenario.tex). Alice, at a battery recycler, asks her orchestrator agent to analyse battery-001. The orchestrator hands the analysis to an XRF agent at a third-party lab, which reads the Digital Product Passport from the manufacturer's registry over MCP. A regulator's incident agent needs emergency access; a broker's harvester agent is the adversary.
